1. Overview

Kelan is an AI-native, zero-telemetry security platform. It is built around one idea: detection is deterministic, and the AI is advisory. Code never leaves the machine — a local LLM (via Ollama) is used only to phrase findings, never to invent them.

The platform ships four families of capability:

FamilyWhat it doesLocation
Scanning engineSAST (AST-aware static analysis), DAST (dynamic web testing), SCA (dependency vulnerabilities), recon (ports), cloud/API-leak audit, runtime analysis (ReDoS, zip bombs), attack-chain correlationkelan/scanner/, kelan/dast/, kelan/plugins/, kelan/analyze/, kelan/recon/, kelan/cloud/, kelan/chains/
Trust engineHybrid LLM + deterministic fallback scoring of connection metrics, with a circuit breaker and Prometheus telemetrykelan/ai/
eBPF kernel shieldXDP packet filter (UDP 9999/AITP v4), per-CPU rate limiting, wire-speed IP blacklistingkelan-ebpf/
PQC key exchangeML-KEM-768 (Kyber768) handshake + key derivationkelan/protocol/

1.1 End Goal

A user installs the repo, connects their local LLM, and runs a single command against a local codebase, a git repository, or a URL. Kelan then takes its time and reports:

  • Broken endpoints & open ports
  • OWASP Top 10 gaps (A01–A10 coverage)
  • Attack chains (correlated evidence across engines)
  • Cloud misconfigurations & API leaks (provider-tied credentials)
  • Runtime chokes (ReDoS, resource exhaustion, zip bombs)
  • Thread-hijacking / data-race surface
  • Token-bucket / rate-limit bypasses (static + live proof)

Output is installable, reportable, and defensible: JSON, SARIF 2.1.0, HTML, terminal, and a CI gate with exit codes.

4. Quick Start

One command, three target kinds — kelan auto-detects and routes to the right plugins:

4.1 Scan a URL (DAST)

kelan run https://www.erasurehq.in/ --only dast --show --json report.json

4.2 Scan a local codebase (SAST + SCA)

kelan run ./kelan --only sast,sca --show

4.3 Scan a remote git repository

kelan run https://github.com/org/repo.git --only sast,sca --sarif out.sarif

6. Plugin System & Scheduler

Every capability is a plugin. Plugins declare what target kinds they apply to, what plugins they depend on, and they exchange data through a shared ScanContext. The Scheduler orders them topologically, runs them, and merges all findings into one FindingSet.

6.1 Writing a plugin

Create a class inheriting from ScanPlugin, implement run(self, ctx) and add its path to `DEFAULT_PLUGIN_MODULES` in `kelan/plugins/__init__.py`.

7. Engines

7.1 SAST

AST-aware static analysis. Code is parsed with tree-sitter into semantic chunks for Python, JavaScript, TypeScript and TSX. Each chunk is sent to the local Ollama model as a standalone unit; verdicts follow a strict JSON schema.

7.2 DAST

Dynamic application security testing against live URLs. Detection is 100% deterministic; the LLM only refines wording.

7.3 SCA

Software composition analysis of dependencies. Fully deterministic — no LLM involved.

7.4 Recon Ports

Non-intrusive async TCP connect scanner (never SYN). Politeness defaults, banner grabbing, service fingerprinting, and open_http publishing for downstream DAST.

7.5 Rate-Limit Audit

Scans code for wall-clock refill, trusted X-Forwarded-For identity, client-controlled keys, per-request bucket initialization (CWE-770, advisory).

7.6 Runtime Analysis (ReDoS)

Runtime chokes with provably static evidence: ReDoS, zip bombs, unbounded loops, shell/code execution sinks, and dangerous deserialization (CWE-1333, CWE-409, CWE-400, CWE-95, CWE-502).

7.7 Cloud & API Leaks

Credential leaks checking (AWS, GCP, Azure, Stripe, SendGrid, Slack, GitHub, OpenAI), instance metadata endpoints, public S3 bucket listing, and tfsec/checkov IaC linting.

7.8 Attack Chains

Rule-based correlation over plugin evidence to identify multi-stage attack paths.

7.9 Concurrency

Advisory-only data-race heuristics: shared mutable global state without locks, time.sleep inside async methods, daemon-thread leaks.

10. Methodology & Design Rules

Unified design philosophy: AI is strictly advisory, scans are deterministic, findings must be backed by evidence, port scans must be opt-in connect-only, and outputs must remain fully offline and zero-telemetry.

11. Testing

.venv/bin/pytest

12. Limitations

Kelan is local-first: SAST runs per-chunk without global call graph; DAST uses static HTML parsing without browser JS execution; eBPF requires root/Linux environments.

13. Roadmap & Checklist

Planned additions: dedicated endpoints analyzer (broken links), auth-aware DAST crawling, concurrency data-race checkers, and native release packages.

14. AI-Assisted Development Context

Kelan is designed to be onboarded cleanly by AI developer agents. Core behavior rules and verified states are persisted in local workspace guides like `SOUL.md`.
